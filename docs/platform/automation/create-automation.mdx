---
title: "Create a translation automation"
description: "Configure triggers, tools, and language resources for repeatable translation work."
---

Create an automation when the same translation task should run more than once. Begin in a project’s **Automations** for project-scoped work, or workspace **Automations** for broader tasks.

## Set up the automation

1. Select **New Automation**.
2. Describe the task, source scope, target locales, and expected output.
3. Choose the **Trigger** from the supported choices below.
4. Attach the tools and knowledge the task needs.
5. Save, then test with a small, recognizable source change.
6. Open **Run History** and inspect the output before relying on the automation.

| Trigger | Configure |
| --- | --- |
| Manually triggered | Run the saved task on demand. |
| On a schedule | Cadence and **Schedule timezone**. |
| GitHub: A push is made, A pull request is made, or A push or pull request is made | Branch patterns and repository. |
| A source file is uploaded | The project whose uploads should start work. |
| A Contentful entry is published | Starts when an entry of the connection's content types is published. |

GitHub triggers require a connected and enabled repository. A Contentful event trigger does not imply that Contentful file sync is available.

To localize Intercom Help Center articles, apply the **Translate Intercom Help Center articles** template. Intercom is not a trigger. Use a scheduled or manual trigger to import articles. After you approve every visible string for a mapped locale, use **Push to Intercom**. See [Localize Intercom Help Center articles](/platform/connections/intercom).

## Example: translate after upload

Choose **A source file is uploaded** for the project and describe the intended task:

```text
Translate uploaded source content into the project's target locales.
Use the linked glossary and project guideline.
Preserve placeholders and leave the output for human review.
```

Upload a small file through Platform or [CLI sync push](/platform/cli), then confirm the matching run and translation output. Make the scope narrower if the task should cover only selected content.

## Pause or change the automation

Pause the automation when new events should stop starting work. Inspect already-started runs separately. Review triggers after changing repository access, branch names, project locales, or language resources.

If no run starts, follow [Automation troubleshooting](/platform/help/automations). For fixed execution order and explicit branches, use [Visual workflows](/platform/visual-workflows).

## Undo edits and unsaved changes

On the new and saved automation pages, **Undo** and **Redo** in the header walk back through your edits in order. Each step covers the whole form (name, trigger, tools, instructions, and related fields), not just the field that had focus. Typing in one text field is grouped into a single step until you leave the field.

- Use **Discard changes** on a saved automation to revert to the last saved configuration. Confirm in the dialog; you can undo that discard from the stack.
- Leaving the page while the form differs from the saved configuration prompts you to stay, save, or discard.
- **Run now** with unsaved edits asks whether to save and run or discard and run.

Running the automation or pushing to an external service no longer reloads the form over edits in progress. If someone else saves while you are editing, the page applies their version as a **system** undo step so you can review or undo it.
