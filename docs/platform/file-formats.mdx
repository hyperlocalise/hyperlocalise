Hyperlocalise Platform brings multilingual content into one workspace. Native
projects accept application resource files, documents, images, video, and Office
files, but translation and editing differ by format. Upload support alone does
not mean a file supports automatic translation or segment editing.

## Native project file support

The table describes the native source-upload and file workflow. Connected TMS
projects follow the [provider's capabilities](/platform/tms).

| File family | Source upload extensions | Translation path | Review | Target export |
| --- | --- | --- | --- | --- |
| Application messages | `.json`, `.jsonc`, `.yaml`, `.yml`, `.arb`, `.strings`, `.stringsdict`, `.xcstrings`, `.ini`, `.toml`, `.xml`, `.resx`, `.resw`, `.properties`, `.php`, `.ftl`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.tsx`, `.mts`, `.cts` | File translation jobs | Segment views | Reconstructed target file |
| Exchange and tabular catalogs | `.xlf`, `.xlif`, `.xliff`, `.po`, `.ts`, `.csv`, `.tsv` | File translation jobs | Segment views | Reconstructed target file |
| HTML | `.html`, `.htm` | File translation jobs | Segment queue and File view | Reconstructed target file |
| Liquid and SVG | `.liquid`, `.svg` | File translation jobs | Segment views | Reconstructed target file |
| Documentation | `.md`, `.markdown`, `.mdown`, `.mkdn`, `.mdwn`, `.mkd`, `.mdx`, `.adoc`, `.asciidoc`, `.asc` | Document translation | File view | Stored target document |
| Subtitles | `.srt`, `.vtt`, `.sbv` | File translation jobs | Segment views | Reconstructed subtitle file |
| Images | `.png`, `.jpg`, `.jpeg`, `.webp` | Image translation workflow | Image file view | Stored target image |
| Video | `.mp4` | Video translation workflow | Video file view | Stored target video |
| Excel workbooks | `.xlsx` | Segment translation | Segment views and File view | Generated target workbook |
| Office documents | `.docx`, `.xls`, `.pptx` | Manual localization in File view | Upload or edit translated file | Stored target file when available |

Office documents are not handled by automatic file translation jobs. Open File
view and upload or edit the translated file there. Other translation workflows require
an enabled provider and the relevant workspace access. A listed extension still
needs valid content for its parser or viewer.

## Excel workbooks

Native projects split each `.xlsx` upload into segments, using the same rules as
the [CLI Excel guide](/cli/reference/formats/xlsx):

- A sheet whose first row has a source-locale column, such as `English` or
  `en-US`, is a string table. Each row is one segment, keyed by its `Key`, `ID`,
  or `Context` column. `Comment` columns become segment context, and
  `Length limit` columns become maximum lengths.
- Any other visible sheet is a free-form document. Each text cell is one
  segment keyed by its address, such as `Pricing!B3`.

Formulas, numbers, cells without letters, and hidden sheets are not segments.
Translate and review the segments in Comfortable, Side by side, or Multilingual
view. File view shows the source workbook next to a read-only preview of the
target workbook generated from those translations. To change the target, edit
its segments.

**Download translations** returns a copy of the source workbook with ready
translations in the target locale's column, or in place for free-form sheets.
Untranslated rows stay empty, and cells for other locales keep their existing
text. Translations already in the workbook are not imported on upload; use
**Import translations** with the filled workbook to load them.

Legacy `.xls` workbooks stay manual Office files. Save them as `.xlsx` to get
segments.

For a complete Platform workflow, start with one of these tutorials:

- [React Intl and ICU messages](/platform/tutorials/react-intl-icu)
- [Vue i18n messages](/platform/tutorials/vue-i18n)
- [i18next and interpolation placeholders](/platform/tutorials/i18next)
- [iOS strings](/platform/tutorials/ios-strings)
- [Android string resources](/platform/tutorials/android-string-resources)
- [XLIFF](/platform/tutorials/xliff)
- [gettext POT and PO](/platform/tutorials/gettext-pot-po), including Unreal Engine `.po` catalogs with rich-text tags
- [Qt Linguist TS](/platform/tutorials/qt-linguist)

Native source upload accepts the same catalog extensions as the
[CLI file-format guides](/cli/reference/formats/overview). Upload
`strings.xml` for Android string resources; other `.xml` files use the generic
XML parser. Direct `.pot` upload is not supported: prepare a source-language
`.po` first, then upload or sync that catalog. Native `.ts` uploads are Qt
Linguist catalogs, not TypeScript locale modules.

For local translation, use the [all-in-one Hyperlocalise CLI](/cli).

## Upload, translate, review, and export

1. [Create a project](/platform/projects/create-project) and choose source and target locales.
2. [Upload your files](/platform/projects/files). The native upload screen accepts up to 10 files per batch.
3. [Start translation](/platform/translation/start), or use the manual Office workflow above.
4. [Review the result](/platform/cat) in the view available for that file family.
5. [Download translated files](/platform/translation/download) and check them in the consuming application.

Uploading alone does not start translation unless you configure a matching
[source-upload automation](/platform/automation/create-automation).

## Is a queue export the same as a translated file?

No. A Content Editor queue export contains filtered segments as CSV, TMX,
XLF/XLIFF, or XLSX, up to 5,000 matching segments. It is useful for review and
handoff. Use the project's **Download translations** action for complete target
files. Document, image, video, and Office file views work with stored files rather
than a segment queue. Excel workbooks are the exception: their download is
generated from segment translations.

## Does Platform support every CLI or TMS file format?

Native uploads now accept the same catalog extensions as the CLI, plus images,
video, and Office files. Local CLI parsing, native Platform uploads, and
provider imports remain separate contracts: a listed extension still needs valid
content, and connected TMS projects follow the provider's import rules.
Supporting an export format does not imply a matching source-upload format.

If an accepted file cannot open, check [upload troubleshooting](/platform/help/uploads).
