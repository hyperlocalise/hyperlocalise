---
title: "2026 October"
description: "Hyperlocalise Platform changes in October 2026."
---

1. **Unreal Engine rich text in gettext PO.** Native projects and the CLI now treat Unreal Engine style tags in `.po` catalogs as placeholders. Translators see chips such as **UE#0** in the [Content Editor](/platform/cat) and keep the markup when they download the file. See [Supported formats](/platform/file-formats), the [gettext POT and PO tutorial](/platform/tutorials/gettext-pot-po), and [Unreal Engine rich text in gettext PO](/cli/reference/formats/gettext#unreal-engine-rich-text).
2. **Merge identical strings.** Exact source-text duplicates collapse into one Content Editor row so you translate them once. Copies that already disagree stay visible as **Different translations**. Turn the project default on from [project settings](/platform/projects/settings), or switch **View** → **Show strings** in the editor. See [Merge strings](/platform/translation/merge-strings) and [Review translations](/platform/cat).
3. **Markdown and MDX document editor.** `.md` and `.mdx` sources open in a document File view instead of a segment queue. Review the stored target document, then [download translations](/platform/translation/download). Capabilities differ from string catalogs; see [Supported formats](/platform/file-formats).
4. **Word documents in File view.** Native projects accept `.docx` uploads. Open File view to inspect formatting and save a translated document. Office files are not handled by automatic file translation jobs. See [Upload source files](/platform/projects/files) and [Supported formats](/platform/file-formats).
5. **PowerPoint in File view.** Native projects accept `.pptx` uploads with the same File view workflow as other Office files. See [Supported formats](/platform/file-formats).
6. **Translation QA.** Workspace QA scans use a configurable check policy. Findings appear inline on compact side-by-side rows, and the QA overview shows charts, alerts, and scan notifications. Failed scans stay diagnosable from the run. See [Improve translation quality](/platform/help/quality), [Resolve translation issues](/platform/translation/issues), and [`hyperlocalise validate`](/cli/commands/validate).
7. **CLI QA validation.** `hyperlocalise validate` runs the same 12-check policy as Cloud QA against one segment or a JSON batch. Point `--policy-file` at a custom policy, or use the built-in defaults. See [`validate`](/cli/commands/validate), [`check`](/cli/commands/check), and [CLI v1.13.1](/changelog/v1-13-1).
8. **Grouped glossary and translation-memory tables.** Glossaries and translation memories use concept- and locale-grouped tables so you can scan terms and segments faster. Import and export still use [TBX, CSV, and XLSX](/platform/glossary-import-export) and [TMX or CSV](/platform/translation-memory-import-export). See [Language resources](/platform/knowledge).
9. **Editable character limits.** Side-by-side review shows length checks on the current string. You can edit the character limit when the project supports it. Fix **Length** before you approve. See [Review translations](/platform/cat) and [Improve translation quality](/platform/help/quality).
10. **Download translated variants.** You can download translated variants of Office files, images, MP4, and Markdown when those target files exist. Use project **Download translations** for complete files, not the queue export. See [Download translated files](/platform/translation/download) and [Supported formats](/platform/file-formats).
11. **Glossary interchange history and Crowdin TBX locales.** Open **Import/export history** on a native glossary to follow queued TBX, CSV, and XLSX runs. Crowdin TBX language IDs such as `de` map to a matching configured locale such as `de-DE` when the mapping is unambiguous. See [Glossary import and export](/platform/glossary-import-export).
12. **Board priority filtering.** Filter Board items by priority when you need an owner for a translation decision. Include the file, key, locale, and decision in the issue. See [Resolve translation issues](/platform/translation/issues) and [Board](/platform/cat#board).
13. **Sectioned project settings.** [Project settings](/platform/projects/settings) save **General**, **Locales**, and **Translation & Content Editor behavior** per section. Check **Source connection** first: native projects and connected TMS projects expose different fields.
14. **New Request in the workspace sidebar.** One-off translation requests are available again from **Agents** → **New Request**. State the project, files, and locales. Recurring work still belongs in [automations](/platform/automation/create-automation). See [Start a translation](/platform/translation/start).
