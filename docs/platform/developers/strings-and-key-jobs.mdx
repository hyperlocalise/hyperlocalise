Use this API on **native projects** to read and update strings, set tags and design links, upload screenshots and mark keys on them, approve or unverify translations in bulk, and manage [key jobs](/platform/translation/jobs). Create and complete key jobs with the [Files and jobs API](/platform/api#create-a-job) on `hyperlocalise.com`; everything on this page uses the public API host.

## Base URL and authentication

```
https://public-api.hyperlocalise.com/v1
```

Send the same [personal access token](/platform/settings#personal-access-tokens) as Projects and Queries:

```
x-api-key: <secret>
```

External TMS projects return `409` with `project_not_native` for string and translation writes.

## Permissions

| Task | Effective permission |
| --- | --- |
| List or read strings, translations, and screenshots | `strings:read` (included with `files:read`) |
| Create or edit strings, upload screenshots, mark keys, send translations to review | `strings:write` (included with `files:write` for roles other than member) |
| Add or remove tags and design links | `strings:write`, and the token owner must be an admin, localization manager, or developer |
| Approve translations in bulk | `translations:approve` (included with `files:write` for admins, localization managers, and reviewers) |
| Manage key job strings and locales, read job lists, update jobs one at a time or in bulk | `jobs:read` / `jobs:write` |

A token never grants more than its owner's role allows. See [Roles and permissions](/platform/workspace/roles).

The [interactive reference](https://public-api.hyperlocalise.com/docs) and [OpenAPI document](https://public-api.hyperlocalise.com/openapi.yaml) list every field and error code.

## Pick strings in bulk

Bulk routes take **one** selector:

| Field | Meaning |
| --- | --- |
| `stringIds` | Up to 1,000 string UUIDs |
| `keys` | Up to 1,000 key names (any file) |
| `tags` | Up to 10 tags; a string must carry **every** tag listed |

Tag and design-link updates and batch review refuse selections larger than 1,000 strings (`too_many_strings`). Adding strings to a key job allows up to 5,000.

Tags match the Content Editor: 1–64 characters, letters, digits, `_`, or `-`.

## Tags and design links

Strings include `tags` and `designUrl` (a link such as a Figma frame). List strings with a repeatable `tag` query parameter; each value narrows the list (AND).

Tag many strings and set a design link in one call:

```bash
curl --fail-with-body \
  -X POST "https://public-api.hyperlocalise.com/v1/projects/$PROJECT_ID/strings/bulk-update" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "content-type: application/json" \
  -d '{
    "keys": ["checkout.title", "checkout.pay"],
    "addTags": ["release-7"],
    "designUrl": "https://www.figma.com/file/example/frame"
  }'
```

The response is `{ "updated": <count> }`. Send `"designUrl": null` to clear the link. Use `removeTags` to drop tags without adding others.

Only the bulk-update route writes tags and links; single-string `PATCH`, create, and batch upsert do not.

## Search strings

`POST /v1/projects/{projectId}/strings/search` takes the list filters in a JSON body, so one call can check up to 1,000 key names and return up to 1,000 strings. Filters combine with AND:

| Field | Meaning |
| --- | --- |
| `keys` | Up to 1,000 exact key names |
| `keyPrefix` | Keys that start with this text, matched literally and case-sensitively |
| `search` | Case-insensitive match on key or source text |
| `filePath` | Strings from one source file |
| `tags` | Up to 10 tags; a string must carry every tag |
| `includeHidden` | Include hidden strings (default `false`) |
| `limit`, `offset` | Page size 1–1,000 (default 100) and start |

```bash
curl --fail-with-body \
  -X POST "https://api.hyperlocalise.com/v1/projects/$PROJECT_ID/strings/search" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "content-type: application/json" \
  -d '{ "keys": ["checkout.title", "checkout.pay", "checkout.old"], "limit": 1000 }'
```

The response has `strings`, `pagination`, and `missingKeys`: the requested keys, in request order, that name no string in the project (in any file, hidden or not). Use it to find which keys to create before you add strings to a key job.

## Screenshots

Upload a PNG, JPEG, or WebP (1 byte to 10 MB) in three steps. The image is the same visual context the Content Editor shows; markers are percent boxes on that image.

1. Create a pending screenshot. The response includes a time-limited PUT URL and the headers to send with it.
2. PUT the image bytes to that URL.
3. Finalize. The screenshot becomes `ready` and `imageUrl` is a time-limited download.

```bash
curl --fail-with-body \
  -X POST "https://public-api.hyperlocalise.com/v1/projects/$PROJECT_ID/screenshots" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "content-type: application/json" \
  -d '{
    "filename": "checkout.png",
    "contentType": "image/png",
    "byteSize": 128,
    "name": "Checkout",
    "markers": [
      {
        "key": "checkout.pay",
        "marker": { "left": 10, "top": 20, "width": 30, "height": 15 }
      }
    ]
  }'
```

PUT the file to `upload.url` with `upload.headers`, then:

```bash
curl --fail-with-body \
  -X POST "https://public-api.hyperlocalise.com/v1/projects/$PROJECT_ID/screenshots/$SCREENSHOT_ID/finalize" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "content-type: application/json" \
  -d '{}'
```

Each marker picks a string with `stringId`, or `key` (and `filePath` when the key exists in more than one file). A missing `filePath` on an ambiguous key returns `400 ambiguous_key`. Add or replace markers later with `POST .../screenshots/{screenshotId}/markers`. Delete one marker or the whole screenshot with `DELETE`.

List screenshots with `GET .../screenshots`. Filter with `stringId` or `key`. Figma-synced frames appear here with `figmaUrl`; this API does not write Figma fields. The [Figma plugin](/platform/connections/figma) still syncs frames on its own.

Without object storage the write routes return `503 screenshot_storage_unavailable`.

## Batch review

**Approve** waiting translations and drafts that have text (Phrase-style verify):

```bash
curl --fail-with-body \
  -X POST "https://public-api.hyperlocalise.com/v1/projects/$PROJECT_ID/translations/approve" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "content-type: application/json" \
  -d '{
    "tags": ["release-7"],
    "locales": ["fr-FR", "de-DE"]
  }'
```

Requires `translations:approve`. Blank translations, rejected translations, text over the string's maximum length, and segments locked in the Content Editor are skipped.

**Send back to review** keeps the current translation text but sets status to needs review (Phrase-style unverify):

```bash
curl --fail-with-body \
  -X POST "https://public-api.hyperlocalise.com/v1/projects/$PROJECT_ID/translations/send-to-review" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "content-type: application/json" \
  -d '{ "keys": ["checkout.title"] }'
```

Requires `strings:write`. Locked segments are skipped.

Both routes return `{ "updated": <count> }`. Omit `locales` to affect every project target language.

## Key jobs after creation

Create a key job with `POST https://hyperlocalise.com/api/v1/jobs` and `type: "keys"`, then use the public API to inspect and adjust it while the job is open.

### List and change membership

```bash
# Strings in the job (hidden strings included)
curl --fail-with-body \
  "https://public-api.hyperlocalise.com/v1/jobs/$JOB_ID/strings?limit=50" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY"
```

Add visible strings (hidden strings and strings in no file are skipped):

```bash
curl --fail-with-body \
  -X POST "https://public-api.hyperlocalise.com/v1/jobs/$JOB_ID/strings" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "content-type: application/json" \
  -d '{ "tags": ["release-7"] }'
```

Remove strings with `DELETE` on the same path and a selection body. A job must keep at least one string.

### Locales and progress

```bash
curl --fail-with-body \
  "https://public-api.hyperlocalise.com/v1/jobs/$JOB_ID/locales" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY"
```

Each locale row includes total, translated, approved, and needs-review counts over the job's visible strings. Progress is computed when you ask; sending a translation back to review lowers counts immediately.

Add or remove target languages with `POST /v1/jobs/{jobId}/locales` and `DELETE /v1/jobs/{jobId}/locales/{locale}` while the job is open. Patch title, description, due date, or owner with `PATCH /v1/jobs/{jobId}`.

### Update many jobs at once

`POST /v1/jobs/bulk-update` applies one change to up to 100 jobs, such as moving every job of a request to a new due date:

```bash
curl --fail-with-body \
  -X POST "https://api.hyperlocalise.com/v1/jobs/bulk-update" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "content-type: application/json" \
  -d '{
    "jobIds": ["'$JOB_ID_1'", "'$JOB_ID_2'"],
    "dueAt": "2026-12-01T09:00:00Z"
  }'
```

It takes the same fields as `PATCH /v1/jobs/{jobId}` (`title`, `description`, `dueAt`, `ownerEmail`; `null` clears all but `title`) and returns `{ "jobs": [...] }` in request order. The update is all or nothing: if one job is missing, provider-backed, or cannot take the owner, no job changes and the error's `details.jobId` names that job. Each job still sends its own job-changed webhook.

Finish the job with `POST https://hyperlocalise.com/api/v1/jobs/{jobId}/complete` on the files-and-jobs host. See [Complete a task for people](/platform/api#complete-a-task-for-people).
