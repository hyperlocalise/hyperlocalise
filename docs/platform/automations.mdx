Automations run repeatable tasks with your connected tools and language resources. Choose the workflow that matches the outcome you need.

| I need to… | Use |
| --- | --- |
| Translate or review after an event or on a schedule | [Create an automation](/platform/automation/create-automation) |
| Move source files and ready translations between GitHub and Platform | [Content sync](/platform/automation/content-sync) |
| Define fixed steps, typed inputs, branches, and retries | [Visual workflows](/platform/visual-workflows) |
| Perform a single task | **New Request** or **Inbox** |

## Where to work

Open workspace **Automations** for tasks that can span projects, or a project’s **Automations** for work scoped to that project. The list shows active and paused automations. Open **Run History** to inspect what happened in a particular run.

Before activating a workflow, check its project, target locales, tools, knowledge, and connected accounts. Test a small example and inspect the result.

## Content sync

Content sync pulls sources into a project and pushes existing ready translations to the destination. It does not generate translations. GitHub is currently the executable provider; other provider movers are not yet available.

## Visual workflows

If **Visual workflows** is available in your workspace, use it to define explicit step order and failure handling. Test a draft, inspect its outputs, then publish a version for automatic runs. See the [advanced bindings and retry guide](/platform/guides/workflow-data-and-retries).

## Monitor and recover

Use **My Jobs** for your own work and automation **Run History** for recurring tasks. Pause an automation to stop new automatic work, then inspect active runs separately. Follow [Automation troubleshooting](/platform/help/automations) when a trigger or step does not behave as expected.
