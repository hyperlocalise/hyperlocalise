Use this API to upload source files, create translation jobs, check progress, and retrieve translated files. It is also the API used by [Platform CLI sync](/platform/cli).

For identity, project discovery, and Queries, use the separate [Projects and Queries API](/platform/developers/projects-and-queries). See [Choose an API](/platform/developers/api-overview) for base URLs and authentication. The OpenAPI document for that API does not describe these file and job routes.

## Base URL

```
https://hyperlocalise.com/api/v1
```

The CLI `hyperlocalise.api_base_url` default is `https://hyperlocalise.com/api`. Paths below are relative to that host, including `/v1`, except job reads.

Read jobs from `https://api.hyperlocalise.com/v1`. See [Read jobs](#read-jobs).

## Authentication

Create a key under **Settings** → **API Keys**. Send it on every request:

```
x-api-key: <secret>
```

Missing, invalid, or revoked keys return `401` with `error: "unauthorized"`. An archived workspace returns `403` with `error: "workspace_archived"`.

### Permissions

| Permission | Used by |
| --- | --- |
| `files:write` | Upload a source file |
| `files:read` | Download a stored file, reconstructed translation, or image variant |
| `jobs:write` | Create a translation job |
| `jobs:read` | Read job status and latest job for a source path |
| `memories:read` | Export translation memory entries as TMX or CSV |
| `memories:write` | Import translation memory entries from TMX or CSV |

Omitting `permissions` grants every scope the key owner can hold. Localization operators receive all six. Job contributors receive every scope except `memories:write`. Members receive `jobs:read`, `files:read`, and `memories:read`.

A key only sees projects the key's creator can access.

## Errors

JSON errors use this envelope:

```json
{
  "error": "machine_readable_code",
  "message": "Human-readable description"
}
```

Branch on `error`. `message` is for debugging and may change. File downloads return the raw body instead of JSON.

## Files

### Upload a source file

`POST /v1/files`

Permission: `files:write`

`multipart/form-data`. Maximum body size is 25 MiB.

| Field | Required | Notes |
| --- | --- | --- |
| `file` | yes | The source file bytes |
| `projectId` | yes | Platform project id |
| `sourcePath` | yes | Repository-style path, max 2048 characters |
| `sourceHash` | no | |
| `commitSha` | no | |
| `workflowRunId` | no | |
| `sourceLocale` | no | |
| `format` | no | |
| `branch` | no | |

`201` response for a native project (resource-keyed):

```json
{
  "file": {
    "id": "file_...",
    "sourceFileVersionId": "...",
    "filename": "en.json",
    "contentType": "application/json",
    "byteSize": 128,
    "sha256": "...",
    "destination": "native"
  }
}
```

TMS-backed projects return `destination: "external_tms"` plus provider fields instead of the stored-file metadata.

This is the same upload `hyperlocalise sync push` performs. It does not create a job.

### Download a stored file

`GET /v1/files/{fileId}/download`

Permission: `files:read`

Returns the file bytes with `Content-Type` and `Content-Disposition`.

## Jobs

### Create a job

`POST /v1/jobs`

Permission: `jobs:write`

JSON body. Discriminate on `type`.

**String job**

```json
{
  "type": "string",
  "projectId": "project_123",
  "stringInput": {
    "sourceText": "Save changes",
    "sourceLocale": "en-US",
    "targetLocales": ["fr-FR"],
    "context": "Primary toolbar button",
    "maxLength": 24
  }
}
```

**File job**

```json
{
  "type": "file",
  "projectId": "project_123",
  "fileInput": {
    "sourceFileId": "file_...",
    "fileFormat": "json",
    "sourceLocale": "en-US",
    "targetLocales": ["fr-FR"]
  }
}
```

`sourceFileId` must already exist in the project (upload first). Locales must match the project. `201` response:

```json
{
  "job": {
    "id": "job_...",
    "type": "file",
    "status": "queued"
  }
}
```

#### Title, deadline and owner

Both job types take these optional top-level fields:

| Field | Type | Notes |
|---|---|---|
| `title` | string, 1–256 | Shown as the job name in the app |
| `description` | string, up to 2,048 | Shown on the job |
| `dueAt` | ISO 8601 date-time with offset | For example `2026-11-15T17:00:00Z`. A date without a time zone is rejected |
| `ownerEmail` | email | Must belong to a member of the workspace. Matched without regard to case. The member becomes the job's owner |

```json
{
  "type": "file",
  "projectId": "project_123",
  "title": "Spring campaign – landing page",
  "description": "Marketing review before Friday",
  "dueAt": "2026-11-15T17:00:00Z",
  "ownerEmail": "pm@example.com",
  "fileInput": {
    "sourceFileId": "file_...",
    "fileFormat": "json",
    "sourceLocale": "en-US",
    "targetLocales": ["fr-FR", "de-DE"]
  }
}
```

[Get a job](#get-a-job) returns `title`, `description`, `dueAt` and `ownerEmail`, `null` when unset.

#### Retries with `Idempotency-Key`

Send an `Idempotency-Key` header to make retries safe. The key is 1–255 printable ASCII characters with no spaces, unique within the workspace, for example an order or ticket ID.

- A retry with the same key and the same body creates nothing. It returns `200` with the job the first request created, its current `status`, and the header `Idempotent-Replayed: true`.
- The same key with a different body returns `422` `idempotency_key_reused`.
- Requests sent at the same time with one key create one job.

```bash
curl --fail-with-body "https://hyperlocalise.com/api/v1/jobs" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -H "Idempotency-Key: order-1042" \
  -H "content-type: application/json" \
  -d @job.json
```

| Status | `error` | When |
|---|---|---|
| 400 | `invalid_job_payload` | Body does not match the schema, including a `dueAt` without an offset |
| 400 | `owner_not_found` | `ownerEmail` is not a workspace member |
| 400 | `invalid_idempotency_key` | Empty, too long, or not printable ASCII |
| 422 | `idempotency_key_reused` | Key already used with a different body |

The CLI does not call this endpoint during `sync push`. Platform automations and the UI create jobs after upload.

### Read jobs

Job reads use a different host from the rest of this API:

```
https://api.hyperlocalise.com/v1
```

Send the same `x-api-key`. `https://hyperlocalise.com/api/v1` no longer serves these routes.

### Latest job for a source path

`GET https://api.hyperlocalise.com/v1/jobs/latest?projectId={projectId}&sourcePath={sourcePath}`

Permission: `jobs:read`

Returns the most recent succeeded file job for that source path, including `outputFiles`.

### Get a job

`GET https://api.hyperlocalise.com/v1/jobs/{jobId}`

Permission: `jobs:read`

```json
{
  "job": {
    "id": "job_...",
    "projectId": "project_123",
    "type": "file",
    "status": "completed",
    "createdAt": "...",
    "updatedAt": "...",
    "completedAt": "...",
    "lastError": null,
    "title": "Spring campaign – landing page",
    "description": null,
    "dueAt": "2026-11-15T17:00:00.000Z",
    "ownerEmail": "pm@example.com",
    "outputFiles": [
      { "fileId": "file_...", "locale": "fr-FR", "filename": "fr.json" }
    ]
  }
}
```

### Job status

`GET https://api.hyperlocalise.com/v1/jobs/{jobId}/status`

Permission: `jobs:read`

Smaller payload with `id`, `projectId`, `kind`, `type`, `status`, timestamps, and `lastError`.

```bash
curl --fail-with-body "https://api.hyperlocalise.com/v1/jobs/$JOB_ID/status" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY"
```

## Translation memories

TMX import and export use the same host as job reads:

```
https://api.hyperlocalise.com/v1
```

Send the same `x-api-key`. These routes wrap the native workspace memory the owner can already see. They do not create memories or list them.

### Export entries

`GET https://api.hyperlocalise.com/v1/translation-memories/{memoryId}/entries/export?format=tmx`

Permission: `memories:read`

Returns TMX 1.4 bytes (`application/x-tmx+xml`). Pass `format=csv` for the Hyperlocalise row layout. Optional `sourceLocale` and `targetLocale` filter to one language pair.

```bash
curl --fail-with-body "https://api.hyperlocalise.com/v1/translation-memories/$MEMORY_ID/entries/export?format=tmx" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -o product.tmx
```

### Import entries

`POST https://api.hyperlocalise.com/v1/translation-memories/{memoryId}/entries/import`

Permission: `memories:write`

JSON body. Inline TMX (or CSV) is applied immediately.

```json
{
  "format": "tmx",
  "content": "<?xml version=\"1.0\"?><tmx version=\"1.4\">...</tmx>"
}
```

`201` includes `imported`, `skipped`, and the import report. Units with a stable `tuid` upsert.

Large files can use `POST .../entries/import/uploads` to receive a signed upload URL, then `POST .../entries/import` with `attemptId` to apply. `GET .../import-attempts/{attemptId}` and `GET .../import-attempts/{attemptId}/download` read the attempt and its source file (`memories:read`).

## Translations and images

These reconstruct current project state. They do not require a job id. That is what `sync pull` uses.

### Download a reconstructed translation

`GET /v1/projects/{projectId}/translations/download?sourcePath={sourcePath}&locale={locale}`

Permission: `files:read`

Returns the translated file bytes for that source path and target locale.

To export only the segments that match Content Editor filters (CSV, TMX, XLIFF, XLSX), use **Download** in the [Content Editor](/platform/cat) queue—not this endpoint.

### Download an image variant

`GET /v1/projects/{projectId}/images/download?sourcePath={sourcePath}&locale={locale}`

Permission: `files:read`

Returns the localized image variant when one exists for that path and locale.

## Example

Upload a source file with curl:

```bash
curl -X POST "https://hyperlocalise.com/api/v1/files" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -F "projectId=project_123" \
  -F "sourcePath=locales/en-US.json" \
  -F "file=@locales/en-US.json"
```

Download the French reconstruction:

```bash
curl -L "https://hyperlocalise.com/api/v1/projects/project_123/translations/download?sourcePath=locales/en-US.json&locale=fr-FR" \
  -H "x-api-key: $HYPERLOCALISE_API_KEY" \
  -o locales/fr-FR.json
```
