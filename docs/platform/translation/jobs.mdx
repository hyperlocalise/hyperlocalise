Open a project’s jobs and select a job to inspect its status, progress, target locales, and source file. Use **My Jobs** to follow your own work across requests.

## Due dates and ordering

Native jobs can carry a **due date** set in the workspace, through visual workflow steps (**Assign task**, **Update job**), or with the MCP `update_job` tool (`dueAt` as ISO 8601, or `null` to clear). Jobs mirrored from an external TMS show the provider due date when one exists; change those in the TMS, not in Hyperlocalise.

On **My Jobs** and the jobs kanban, open work is sorted with the soonest due date first; jobs without a due date appear after dated work. Cards and the job detail page show relative due text and highlight overdue items. **Pick assignee** rules can treat urgent work differently using **Due within (hours)** when the workflow passes a due date into the step.

## File translation activity

Native **file translation** jobs (agent jobs on uploaded project files) show an **Activity** feed on the job detail page. While the job is **Queued** or **Running**, the page refreshes the feed and status about every three seconds; polling stops in a terminal state.

The feed includes:

- **Created** — when the job was created and by whom, when known.
- **Run cards** — one card per workflow attempt, labeled with the Hyperlocalise agent. The badge moves through **Preparing** (context, glossary, translation memory, reading the file), **Translating**, then **Finished**, **Failed**, or **Stopped** if you cancel or mark the job failed.
- **Per locale** — waiting, translating, retrying, done, or failed, with translated string counts (for example `120 / 340`) and how many strings were reused from translation memory or existing translations.
- **Detailed steps** — expand a run card to see stages such as strings extracted, translation memory reuse, per-locale progress updates, locale retries, and completion.
- **Your actions** — cancel, retry, or mark as failed appear as separate rows when you use those controls.

Jobs started before activity logging was enabled may show only **Created** and the current status. If activity fails to load, an inline message appears; the rest of the job page still works. The jobs list and kanban do not show this feed yet; open the job detail page to follow progress.

## Reports on a job

When workspace **Reports** is enabled, native jobs include a **Report** tab with that task's word counts, translation-memory match bands, time logged, and (for administrators and localization managers) cost and pricing. Match analysis runs shortly after the job is created; the tab shows progress until scoring finishes. See [Reports](/platform/workspace/reports).

## Understand status

| Status | What to do |
| --- | --- |
| Queued | Wait for execution to start; inspect the job if it remains queued unexpectedly. |
| Running | Follow progress before submitting the same work again. |
| Waiting for review | Open the job and complete the review it requests. |
| Succeeded | Inspect the output; generation success is separate from translation approval. |
| Failed | Read the error, fix its cause, and retry when eligible. |
| Cancelled | The job was stopped; create a new job if the work is still needed. |

Provider-backed jobs can expose different status and action names. Use **Open in provider** when the connected system owns the job.

## Retry a job

For a translation job in a queued or failed state, the detail page can offer **Retry job**. Check the source file, target locales, permissions, usage, and error first. Select **Retry job** once, then follow the queued attempt.

Retrying without fixing a malformed file or disconnected provider is unlikely to help. See [Translation failures](/platform/help/translation-failures).

## Stop an active native job

For a native job that is queued, running, or waiting for review, select **Cancel job** and confirm when you want to stop it. Cancellation does not undo output or external actions that already completed.

**Mark as failed** is a separate recovery action for active native jobs. It prevents the current workflow from later updating the job and removes it from the active queue. Use it when you have decided to abandon that attempt, rather than treating it as a refresh button.

## Hand off the result

Use **Open Editor** when available. Check [review permissions](/platform/workspace/roles) if approval is unavailable. Keep the job link when [contacting support](/platform/help/contact-support).
