title: "MCP server"
description: "Connect coding agents to Hyperlocalise Platform over the Model Context Protocol."
---

Hyperlocalise hosts an MCP (Model Context Protocol) server so agents such as Claude Code, Codex, and Cursor can read projects, source files, translation keys, glossaries, jobs, and Board items from your workspace.

The server uses OAuth with PKCE. After you approve access, the agent receives a bearer token scoped to one organization and your current membership role.

## Connect an agent

Open your workspace **Overview**. The **Connect your agent** card shows setup snippets for Claude, Codex, and Cursor.

| Client          | Typical setup                                                                            |
| --------------- | ---------------------------------------------------------------------------------------- |
| **Claude Code** | `claude mcp add -t http hyperlocalise https://hyperlocalise.com/mcp`                     |
| **Codex**       | `codex mcp add hyperlocalise --url https://hyperlocalise.com/mcp`                        |
| **Cursor**      | Add an HTTP MCP server named `hyperlocalise` pointing at `https://hyperlocalise.com/mcp` |

The first connection opens a browser sign-in and consent flow. Pick the organization the agent should use. Codex may also require `codex mcp login hyperlocalise` after adding the server.

<Note>
  MCP auth is separate from organization [API keys](/platform/settings) and [personal access
  tokens](/platform/settings#personal-access-tokens). Agents authenticate through OAuth, not
  `x-api-key`.
</Note>

## Verify the connection

Ask your agent:

```text
List the Hyperlocalise projects I can access. Do not change anything.
```

Confirm the agent returns projects from the intended workspace. Then ask it to list the source files in one project. An empty list can mean there is no content yet or your account lacks access; it does not by itself mean the connection failed.

## Start a scoped task

Give the agent a project, source path, and target locale. Ask it to inspect status before starting translation so you can see whether the work already exists. Review generated output before approving or delivering it.

Use the [MCP tool reference](/platform/developers/mcp-tools) for tool inputs, permissions, and detailed errors.

## Access and troubleshooting

The session uses your current workspace membership and project access. API keys and personal access tokens do not replace the OAuth sign-in step.

| Symptom | What to do |
| --- | --- |
| Sign-in or consent repeats | Sign out and retry, or use a private window. |
| The wrong projects appear | Reconnect and select the intended organization during consent. |
| A project is missing | Check your workspace membership and team access. |
| A write returns `forbidden` | Check whether your role permits the requested action. |

If a tool fails, keep its error code and follow the [reference's troubleshooting table](/platform/developers/mcp-tools#troubleshooting).

## Connect an external MCP server to an automation

To let a saved automation call a remote server, add an **MCP Server** connection in **Integrations**. Follow [external MCP connections](/platform/integrations#mcp-server-connections). This is a separate setup from connecting your agent to Hyperlocalise.
