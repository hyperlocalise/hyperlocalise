title: "Add translation guidelines"
description: "Give translators and agents the tone, audience, and product context they need."
---

Use **Guideline** for instructions that cannot be expressed as a term pair: audience, voice, product context, market preferences, and examples. Put required term translations in a glossary and reusable sentence pairs in a translation memory.

Every guideline is a document. Upload a file, or type Markdown text that Hyperlocalise saves as a document for you. There is no separate typed note: whatever you write becomes a document record with its own revisions.

## Scope

Workspace **Guideline** stores shared context as org-wide documents with no project set. Project **Guideline** stores project-specific context as documents owned by that project. The workspace list only shows org-wide files. A project file is not visible on the workspace page, and one project never sees another project's files.

Org-wide documents apply to no project until you assign them. Open a document to assign it to specific projects in its **Projects** section. Assignment filters translation, guideline checks, and automation recall for that project. The project Guideline page does not change assignment.

## Write or upload a guideline

1. Open workspace **Guideline** for shared context, or the project’s **Guideline** for project-specific context.
2. Select **Add sources** to open the **Upload guideline** page, then drop a file or select **Markdown/Text** to type the guideline. Typed text is saved as a Markdown document.
3. Wait for the document's status to change from **Processing** to **Ready** under **Uploaded guidelines**.
4. Open the document and assign it to projects: an unassigned org-wide document is not used anywhere.

To change a document later, open **Edit** on its row: editing the content saves a new revision, editing only the title updates it in place. Supported uploads are PDF, DOCX, Markdown, and plain text, up to 25 MB and one file at a time. Hyperlocalise extracts the text and indexes it for search. Scanned PDFs without a text layer show **Failed** with “No readable text was found”; export the document with selectable text and upload it again. Very long files are truncated, and the document shows a notice when that happens. Options marked **Coming soon**, such as connector-based imports, are not available upload paths.

Admins and localization managers can upload, edit, delete, and assign documents. Other members can view them.

### Choose what always applies

Turn on **Always apply** for a short document that must be used in full every time, such as a list of banned words. Other documents are searched and Hyperlocalise keeps only the passages relevant to the text being translated or checked. Keep long reference material searchable so it does not crowd out more relevant guidance.

Uploaded documents apply to every target locale, so state the market inside the document when a rule only applies to one language.

### Setup wizard guidance

The engine-setup wizard keeps a managed document titled **Setup wizard guidance** with the voice and rules it learned from your site. Edit it like any other document: the wizard merges into your edits instead of overwriting them, so your changes are preserved. Do not rename it; the wizard finds it by that exact title and creates a new one if it cannot. Like every org-wide document, it applies to no project until you assign it on its page.

## What to include

Use a short document with concrete examples:

```text
Audience: people buying their first subscription.
Tone: clear, warm, and direct. Avoid slang.
Product names: keep Hyperlocalise unchanged.
French: use “vous” consistently.
Buttons: prefer a short action verb.
Preserve variables, URLs, and ICU message structure.
```

Add the approved wording and a counterexample when a rule could be ambiguous. State the market explicitly when regional usage matters.

## Use it in translation

Attach the relevant knowledge when configuring an [automation](/platform/automation/create-automation), and name it in one-off requests. Review a representative sample to confirm the instruction has the intended effect. Updating a guideline does not retroactively rewrite or approve existing translations.

Keep a clear owner for the document so project and workspace guidance do not give conflicting instructions. See [Language resources](/platform/knowledge).

## Check text against guidelines

Agents can check source text or translations against your guidelines with the [`check_guidelines` MCP tool](/platform/developers/mcp-tools#guideline-checks). Send up to 50 segments with an optional project and target locale. Each finding points to the exact text that breaks a rule and quotes the guideline passage it relies on. Findings without a supporting guideline passage are discarded.

An empty result means no guideline violation was found. It does not confirm that the translation is accurate, so keep reviewing a sample. Each checked segment counts toward your plan's guideline check usage.
