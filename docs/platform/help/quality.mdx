title: "Improve translation quality"
description: "Diagnose terminology, style, placeholder, and translation-memory problems."
---

Fix the affected translation, then improve the resource or instruction that caused the problem. A successful generation job does not establish that the wording is ready for publication.

| Symptom | What to inspect |
| --- | --- |
| Wrong product term | Glossary term, locale, project link, and forbidden alternatives. |
| Wrong tone or regional wording | Guideline audience, market, examples, and contradictory instructions. |
| Repeated outdated phrase | Translation-memory source/target pair and its suitability for the current context. |
| Broken variables or plurals | Exact placeholder names, ICU syntax, and unused plural cases. |
| Broken inline tags | Export the filtered queue, repair tags in the bilingual file, then re-import it on a native project. |
| Text is too long | Length checks and the actual destination layout. |
| Old approved wording survives generation | Source meaning changes and the existing approval. |

## Correct and verify

1. Open the affected segment in the [Content Editor](/platform/cat).
2. Compare the source, target, glossary hits, and memory suggestions.
3. Correct the target and resolve visible checks.
4. Approve with an authorized reviewer.
5. Search for other affected occurrences, or [merge identical strings](/platform/translation/merge-strings) when the same source should share the corrected wording.

A glossary is for terms; a guideline is for instructions; a translation memory is for reusable sentence pairs. Use the appropriate [language resource](/platform/knowledge) rather than placing every rule in one document.

## Project QA

On a native project, open **QA**, then **Check settings**. Turn on **Guidelines**, set **Warning** or **Error**, and **Save check settings**. Run a scan manually or turn on the daily scan.

With **Guidelines** on, each scan checks stored translations against your [guideline documents](/platform/knowledge/guidelines) and saves each issue as a finding. Empty or whitespace-only targets are skipped. Warnings do not block saving in the editor. An error blocks saving only after the editor has already reported it.

Each classified segment counts toward your plan's weekly guideline check allowance. A cache hit is not billed. Scans save a short warning for each flagged segment. Choose **Explain** on a row to load the cited passage, reason, and optional replacement; explaining spends AI credit. If the allowance runs out, a translation is too long to check, or a batch cannot be reached, the scan still finishes its other checks, keeps guideline findings it already saved, and leaves older guideline findings in place. The run notes that guideline checks were incomplete, so a clean guideline count is not a full recheck.

### Quality score

A quality score turns a scan's findings into one number per language, so you can set a pass mark instead of reading every finding. In **Check settings**, turn on **Quality score** and set the **Pass threshold** (95 by default).

Each finding costs points by severity: **Minor** 1, **Major** 5, **Critical** 25. A warning counts as minor and an error as major unless you choose a different penalty for that check. A language scores `100 × (1 − points ÷ source words)`, floored at 0, and passes when it reaches the threshold and has no critical finding.

Source words are counted with the project's source language. Chinese, Japanese, Thai, Lao, Khmer and Burmese, written without spaces, are counted by word, not by sentence.

Ignoring or reopening a finding updates the latest scan's score at once. Changing penalties or the threshold applies from the next scan.

### Quality estimate

The **Estimated quality** check has AI score every translated segment from 0 to 100 for how ready it is to publish without edits, with a one-line reason. Turn it on in **Check settings** and set its severity. Segments scored below the **Estimate threshold** (70 by default) become findings, so they count toward the quality score and can send work to review.

A scan only re-scores a segment when its source text, translation or content domain changed; unchanged segments keep their earlier score. Empty translations and very long segments are not scored. If the estimator stops part-way, the scan keeps the estimates it made, leaves older estimate findings open, and notes that estimates were incomplete. The QA overview shows the average estimate and how many segments fell below the threshold.

### Content domain

Set **Content domain** to **Medical**, **Legal** or **Financial** for regulated content. The domain:

- Tells the estimator which changes matter most, such as a dosage, a defined term or an amount, and to score them as severe.
- Raises the lowest estimate threshold: 85 for medical and legal, 80 for financial.
- Makes every [Run QA](/platform/visual-workflows#check-translations-with-qa) workflow step report that the work needs human review, whatever the score.

### Review findings

On the project **QA** page or workspace **QA** overview, open the findings table to work through results from the latest scans.

1. Use filters for check type, severity, locale, and status.
2. Select **Open editor** on a row to fix the string in context.
3. For an open **Guidelines** finding, choose **Explain** when you need the full reasoning before you change the translation.
4. Select one or more rows, then **Ignore selected** and enter a reason when the finding is a false positive or accepted deviation. **Undo** on an ignored row reopens it.
5. Select rows and **Create issues** to open Board items linked to the findings, or **Create Linear issues** when [Linear is connected](/platform/connections/linear#file-qa-findings-in-linear) to file up to 25 findings at once in a Linear team.

Reviewers, localization managers, and admins can ignore findings and create issues. Translators can read findings and use **Explain** where it is shown. Filing Linear issues requires the same approve permission as ignoring findings.

## Test the improvement

Run a small representative translation request with the updated resources and review its output. Updating resources does not retroactively rewrite existing translations. Include ambiguous wording, plural messages, and short labels in the sample when those caused the original issue.
