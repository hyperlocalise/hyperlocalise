# Cloud customer help center

## Approved scope

The user approved restructuring the Cloud documentation, rewriting content for customers, adding help articles, and publishing advanced guides in the same change. Existing English CLI work and localized documentation remain intact.

## Design

Organize around the customer journey: first translation; projects and files; translation and review; language resources; automation; connections; website research; workspace administration; developer integrations; troubleshooting. Use collapsed groups for secondary paths and retain existing page URLs. The landing page routes readers by task instead of framework.

Each help article answers a concrete question, gives prerequisites and UI steps, explains the expected result, and links to recovery instructions. Advanced guides cover source updates, review handoffs, GitHub content sync, workflow data bindings, and retry recovery. Distinguish uploading from generation, job completion from approval, queue exports from full target files, and account connections from executable sync.

Verify behavior against application source. Do not advertise unavailable integration movers or prototype research screens. Move operator setup and private organization API material into an ignored engineering archive. Retain supported public API, CLI, and MCP documentation for customer developers. Preserve contributor docs outside the Cloud navigation.

## Validation

Run Mintlify validation and broken-link checks from docs, check whitespace, inspect representative rendered pages, and verify English CLI and localized navigation are unchanged by this Cloud work. No application code changes or live paid actions are required.
