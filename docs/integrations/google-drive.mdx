# Google Drive

Connect Google Drive with WorkOS Pipes, choose folders on the Integrations page, and use a workspace automation to import supported files into a Hyperlocalise project. Translations are written back under per-locale subfolders as `[locale] Filename.ext`.

## Setup

1. In **Integrations → Guidelines**, connect **Google Drive** (custom OAuth button; not the generic Pipes widget).
2. After connecting, use **Add folders** to select My Drive or Shared Drive folders. You can add or remove folders anytime.
3. Create or edit a workspace automation with the **Translate Google Drive files** skill, attach a native project, and select the connected folders.

Platform operators must configure WorkOS Pipes and Google OAuth before customers can connect in production. See [Google OAuth setup (WorkOS Pipes)](#google-oauth-setup-workos-pipes) below.

## Google OAuth setup (WorkOS Pipes)

Hyperlocalise connects through WorkOS Pipes with provider slug **`google-drive`**. Tokens call the Google Drive API v3 (list shared drives, browse folders, export Google Workspace files, download binaries, create locale subfolders, and upload or update translated files). All of those operations use `supportsAllDrives=true` so **My Drive** and **Shared drives** behave the same.

### Required OAuth scope

Configure **exactly this scope** on the WorkOS Google Drive provider (and on your Google OAuth client consent screen):

| Scope | Required |
| --- | --- |
| `https://www.googleapis.com/auth/drive` | **Yes** |

This is a **restricted** Google scope. Production apps must complete [Google OAuth app verification](https://support.google.com/cloud/answer/9110914) for restricted Drive scopes before all users can connect without an "unverified app" warning.

**Do not substitute narrower scopes** for this integration:

| Scope | Why it is not enough |
| --- | --- |
| `https://www.googleapis.com/auth/drive.readonly` | Import works, but push cannot create locale subfolders or upload translated files. |
| `https://www.googleapis.com/auth/drive.file` | Only covers files the app created or opened with a picker. Hyperlocalise must read existing files in folders the admin browses and write into those folders without per-file picker grants. |

Optional future work (Changes API incremental sync) uses the same **`drive`** scope; no extra scope is required beyond what import and push already need.

### WorkOS Dashboard

1. Open **Pipes** and enable the **Google Drive** provider with slug **`google-drive`** (must match Hyperlocalise `PIPES_PROVIDER_SLUGS`).
2. Under provider scopes, add **`https://www.googleapis.com/auth/drive`**. Do not request unrelated Drive scopes unless you have a separate product reason.
3. Add a short **description** for the consent widget (for example: read selected folders for translation import and write translated copies under locale subfolders).
4. **Sandbox:** WorkOS shared Google credentials are enough for early testing.
5. **Production:** Create your own Google OAuth client (see below), paste **Client ID** and **Client secret** into WorkOS, and use the **Redirect URI** WorkOS shows for that provider.
6. Grant roles that manage Integrations permission to use the Pipes widget / authorize-url flow for `google-drive`.

### Google Cloud Console

1. In the project that owns the OAuth client, enable the **[Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com)**.
2. Configure the **[OAuth consent screen](https://console.cloud.google.com/apis/credentials/consent)** (Internal for workspace-only testing, External for customers).
3. Create an **OAuth client ID** (type **Web application**).
4. Add the **Authorized redirect URI** from the WorkOS Google Drive provider page (copy it from WorkOS; do not guess).
5. On the consent screen, add scope **`https://www.googleapis.com/auth/drive`** (Display: "See, edit, create, and delete all of your Google Drive files").
6. Submit **verification** for the restricted scope before general availability if the app is External.

### Smoke check after setup

1. Connect Google Drive from **Integrations → Guidelines** in staging.
2. Expand **My Drive** and a **Shared drive** in **Add folders** (403 here usually means missing **`drive`** scope or Drive API disabled).
3. Save a folder, run **Translate Google Drive files** import, then **Push to Google Drive** and confirm files appear under `{folder}/{locale}/`.

## Supported files

| Source | Ingest format |
| --- | --- |
| Google Docs | DOCX |
| Google Sheets | XLSX |
| Google Slides | PPTX |
| PDF | Markdown (text extraction via unpdf) |
| Other supported project formats | Original extension (JSON, CSV, HTML, MD, DOCX, etc.) |

## Write-back

For each target locale (defaults to the project’s target locales), Hyperlocalise creates or updates:

`ParentFolder/{locale}/[{locale}] OriginalName.ext`

Google Docs, Sheets, and Slides are uploaded back as native Google file types when the source was a Google app file.

## Known limitations

- If Google Drive auto-converts an upload to a Google Doc, export returns DOCX and the original format (for example `.md`) cannot be recovered.
- Google Apps Script, Drawings, Forms, and Sites are not translated.
- Image, video, and audio files are skipped.
- ZIP and other archive files are skipped.
- PDF translations are Markdown text only; layout is not preserved.

## Limits

- **5,000** files shown in the Integrations folder browser (per folder listing).
- **10** nested folder levels when walking connected folders.
- **100 MB** maximum file size per file.
