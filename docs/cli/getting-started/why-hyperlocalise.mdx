Hyperlocalise CLI connects your codebase to Hyperlocalise Platform. Together, they
give developers, translators, and managers a shared path from source content to
translations ready for review and release.

## Keep developers and reviewers in sync

Upload source files from your repository with `hyperlocalise sync push`. Your team
can translate and review them in Platform, then you retrieve project translations
with `hyperlocalise sync pull`. Review the resulting diff before release.

Developers keep their Git and CI workflow. Reviewers use the
[translation editor](/platform/cat) without setting up a local development environment.

## Manage more than files

Use Platform to organize projects and target languages, maintain glossaries and
translation memory, and track translation jobs. [Automations](/platform/automations)
help you repeat translation tasks as content changes.

A source upload does not automatically generate translations. Start a translation
request or configure a Source upload automation for that project.

## Connect your release workflow

Preview sync operations with `--dry-run` before writing files. Keep API keys in
your CI secret manager and use explicit push and pull steps in your pipeline.
The [connection guide](/platform/cli) covers configuration and credentials.

## Start with one project

1. [Open Hyperlocalise](https://www.hyperlocalise.com) and [create a project](/platform/projects/create-project).
2. [Install the CLI](/cli/getting-started/install).
3. [Connect your repository](/platform/cli) and upload one source file.
4. Translate and review in Platform, then pull the result into your repository.

## Already have a translation workflow?

You can use [local AI translation](/cli/getting-started/quickstart) without a
Platform account. The CLI also provides [TMS integrations](/cli/storage/overview)
for supported operations in existing accounts. Check each provider's documented
commands and limits before replacing an existing script.

[Compare the three workflows](/cli/getting-started/workflows) to choose the right
configuration and credentials for your project.
