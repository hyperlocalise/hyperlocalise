One CLI for your localization stack. Hyperlocalise combines local AI translation,
translation checks, and commands for Crowdin, Lokalise, Phrase Strings, and
Smartling in one installation. Work in your repository, automate CI, and connect
to Hyperlocalise Platform when you need a shared workspace.

## One CLI for your TMS workflows

Use the command family for your provider. Each has its own authentication,
configuration, and supported operations.

| Your platform | What you can do | Start here |
| --- | --- | --- |
| Crowdin | Upload sources, download approved translations, manage branches, and exchange glossary/TM files | [Crowdin CLI workflows](/cli/commands/crowdin) |
| Lokalise | Upload locale files, wait for imports, and download translations | [Lokalise CLI workflows](/cli/commands/lokalise) |
| Phrase Strings | Reuse supported `.phrase.yml` settings to push sources and pull translations | [Phrase Strings CLI workflows](/cli/commands/phrase) |
| Smartling | Upload sources, inspect file status, and download published translations | [Smartling CLI workflows](/cli/commands/smartling) |
| POEditor or LILT AI | Sync flat JSON translation entries through an experimental adapter | [TMS integrations](/cli/storage/overview) |
| Hyperlocalise Platform | Upload source files and retrieve existing project translations | [Connect the CLI](/platform/cli) |

You can use local translation without a TMS or Platform account. Choose an
[AI provider](/cli/providers/overview) independently of your translation platform.
See the [compatibility matrix](/cli/storage/overview) before moving an existing
script: one CLI does not mean every provider has identical commands or features.

## The everyday workflow

1. Map source files to target paths in `i18n.yml`.
2. Preview the translation plan with `hyperlocalise run --dry-run`.
3. Generate translations with `hyperlocalise run`.
4. Review the diff and run `hyperlocalise check`.
5. Commit the translated files and `.hyperlocalise.lock.json`.

The lockfile records translation progress so later runs can skip completed work.
See [local translation](/cli/workflows/local-generation) for the full workflow.

## Is Hyperlocalise the best localization CLI for your team?

Choose Hyperlocalise when you want local AI translation, Git-based review, and
multiple TMS command families in one tool. Compare the supported operations with
your actual scripts: a provider's official CLI may be a better fit when you need
its full API surface or exact flag compatibility. See [why Hyperlocalise](/cli/getting-started/why-hyperlocalise)
for selection criteria and [TMS integrations](/cli/storage/overview) for limits.

## Can I use one CLI with every TMS?

Hyperlocalise supports the providers listed above. It does not include an adapter
for every TMS, and file workflows differ from entry sync. For an unlisted provider,
use its own supported import/export workflow; local translation support alone does
not establish a direct integration.
