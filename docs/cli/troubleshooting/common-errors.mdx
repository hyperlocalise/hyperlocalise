## `i18n.yml already exists; use --force to overwrite`

Your project already has a configuration. Open `i18n.yml` and update its locales, paths, or provider settings, then preview with `hyperlocalise run --dry-run`.

If you deliberately want to replace it with a starter, save a copy first, then run `hyperlocalise init --force`. This overwrites the existing configuration. See [Configure your project](/cli/configuration/i18n-config).

## `sync requires top-level "hyperlocalise" or "storage.adapter"`

Choose the destination before adding configuration:

- For Hyperlocalise Platform, add the top-level `hyperlocalise` block from [Connect the CLI](/platform/cli).
- For experimental TMS entry sync, add `storage.adapter` and the provider's `storage.config`. See [TMS integrations](/cli/storage/overview).
- For provider file operations, use the provider command family, such as `crowdin` or `phrase`, with its own configuration.

If both `hyperlocalise` and `storage` are configured, Platform takes precedence. Use separate config files when you need both destinations.

## `unsupported output format`

Cause: wrong `--output` value.

Fixes:

- `status`: only `csv`
- `sync`: `text`, `json`, or `markdown` (also accepts `md`)

## `unsupported file extension` during `run`

Cause: a mapped source or target file uses an extension not supported by the local parser.

Fixes:

- use one of: `.json`, `.jsonc`, `.yaml`, `.yml`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.mts`, `.cts`, `.properties`, `.ini`, `.xml`, `.resx`, `.resw`, `.arb`, `.xlf`, `.xlif`, `.xliff`, `.po`, `.html`, `.liquid`, `.md`, `.mdx`, `.adoc`, `.asciidoc`, `.asc`, `.strings`, `.stringsdict`, `.xcstrings`, `.csv`, `.tsv`, `.toml`, `.ftl`, `.srt`, `.vtt`, `.sbv`, `.svg`
- verify bucket `from` and `to` paths resolve to the expected file names

For `.xcstrings`, ensure the catalog has a `strings` object and either a source-language localization for variant/substitution entries or simple catalog keys that can be used as source text.

## Provider auth failures

Check the credentials for the operation you are running. Local generation uses [AI provider credentials](/cli/configuration/provider-credentials); Platform sync uses a [Platform API key](/platform/cli); provider commands use that TMS's credentials.

Confirm the environment variable name in the configuration and set its value in the same shell or CI job. Check the account's access and whether the credential was revoked. Retry only after correcting the cause.
