XLIFF exchanges source and target text between localization tools. Hyperlocalise translates XLIFF 1.2 and 2.x structures, including independent segments and inline codes. Writeback preserves source text and creates missing target elements.

Supported extensions: `.xlf`, `.xlif`, `.xliff`.

## Source file

Save this example as `locales/en-US/messages.xlf`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<xliff version="1.2">
    <file source-language="en-US" target-language="es-ES" datatype="plaintext" original="messages">
        <body>
            <trans-unit id="welcome">
                <source>Welcome</source>
                <target></target>
            </trans-unit>
        </body>
    </file>
</xliff>
```

## Configure your files

Use this `i18n.yml` for the example, or add its file mapping to your existing bucket.
See [path templates](/cli/configuration/path-templates) for other layouts.

```yaml
locales:
    source: en-US
    targets:
        - es-ES

buckets:
    messages:
        files:
            - from: locales/en-US/messages.xlf
              to: locales/{{target}}/messages.xlf

llm:
    profiles:
        default:
            provider: openai
            model: gpt-5.2
```

## Translate

[Install the CLI](/cli/getting-started/install) and set `OPENAI_API_KEY` in your
project's `.env.local` or shell. You can also configure another
[AI provider](/cli/providers/overview).

```bash
hyperlocalise run --dry-run
hyperlocalise run
```

The dry run previews the work. The second command writes translations to the
configured target path and updates the lockfile.

## Behavior and limitations

- Supports XLIFF 1.2 `trans-unit` and segmented `seg-source` markers, and XLIFF 2.x `segment` elements inside `unit`. XLIFF 2.x `ignorable` content stays unchanged.

- Single-segment units keep their existing unit key: `id`, then `name`, then `resname`. Multiple segments use `unit-key#segment=segment-id`, with a URL-escaped segment ID. XLIFF 1.2 uses each marker's `mid`. XLIFF 2.x segments without IDs use `unit-key#segment-index=1`, `unit-key#segment-index=2`, and so on. Assign stable segment IDs to keep keys consistent when reordering segments.

- Parsing reads a non-empty target per segment before falling back to that segment's source. Use source catalogs with empty targets for a first translation.

- Writeback updates existing targets or creates missing targets without replacing source text. It preserves untouched XML bytes, namespace prefixes, target attributes, comments, and metadata. For a missing segmented XLIFF 1.2 target, it copies the `seg-source` structure and updates the translated markers. An existing target without matching markers produces an error rather than guessing segment boundaries.

- Inline code identities, attributes, and native code payloads must match the source. Malformed or changed inline codes produce an error. Plain-text replacements with XML-special characters are escaped when they are not valid XML fragments.

- Duplicate unit or segment keys produce an error. Unit-level replacement values for multi-segment units also produce an error. Translate each segment independently.

- Multi-segment keys differ from the previous combined unit key. The first run after upgrading may translate those segments again and write new segment-level lockfile entries.
