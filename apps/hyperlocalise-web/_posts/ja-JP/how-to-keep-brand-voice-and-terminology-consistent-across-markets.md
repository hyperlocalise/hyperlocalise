多くの企業は、一度の大きなミスでブランドの一貫性を失うわけではありません。ひとつひとつの文言を通じて、少しずつ失っていきます。

ある市場では製品名が翻訳され、別の市場では英語のままになっている。ドイツ語のランディングページには、法務部門が2年前に禁止した最上級表現が紛れ込む。日本語のヘルプセンターでは、記事を書いたベンダーによって敬体とカジュアルな文体が使い分けられる。誰かが意図的にルールを破ったわけではない。ただ、そのルールがライターや翻訳者、AIモデルの作業環境になかっただけだ。

このガイドでは、対応言語が数言語を超え、チームも1つではなくなった後に、各市場でブランドボイスと用語を一貫させる方法を説明します。特定のツール向けではなく、どの市場でも同じルールを適用する必要があるローカライズ担当リード、ブランドやコンテンツの責任者、コンプライアンスチームを対象としています。

> **核心的な問題は、優れたガイドラインを書くことではありません。文が作成または承認されるその瞬間に、適切なルールを適切な人やモデルに示し、そのルールが適用されたことを証明することです。**

## 「一貫性」とは実際には何を意味するのか

チームはブランドの一貫性を一つのものとして捉えがちです。実際には、少なくとも4つの別々の課題があり、それぞれに異なる管理方法が必要です。

| レイヤー                | 一貫性を保つ必要があるもの                                      | よくある問題                                                              |
| --------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 用語           | 製品名、機能名、UI用語、翻訳禁止語  | 同じサイト内で「ワークスペース」が3通りに翻訳されている |
| ブランドボイスとトーン  | 文体、フォーマル度、文のスタイル、パーソナリティ                | ウェブサイトではフォーマルなドイツ語、アプリではカジュアルなドイツ語                 |
| 主張およびコンプライアンス | 承認済みの表現、開示事項、禁止されている主張、規制対象の表現 | ある市場では認められていても、別の市場では認められない最上級表現や健康に関する主張 |
| 市場適応     | 市場ごとに意図的に変えるべきもの                      | 何の意味も持たない市場に、米国中心の訴求材料をそのまま持ち込むこと    |

最後の行が重要です。一貫性とは画一性ではありません。優れたガバナンスモデルは、すべての場所で同一でなければならないもの、市場ごとのルールに従うもの、そして現地の判断に委ねられるものを明確にします。

## 規模が大きくなると一貫性が崩れる理由

ライターが一人で言語が一つなら、一貫性を保つのは簡単です。市場、チーム、ベンダーが増えるにつれて、予測できる理由で崩れていきます。

**ルールはあまりにも多くの場所に散在しています。**ブランドブックはGoogle Drive上のPDFです。市場メモはNotionにあります。法務部は承認済みの開示文言をSharePointで管理しています。用語集は、前四半期にTMSからエクスポートされたスプレッドシートです。レビュー担当者の判断はコメントスレッドに残っています。そのすべてを把握している人は一人もいません。

**ルールは参照されるのではなく、コピーされます。** TMSやベンダー向けブリーフ、AIプロンプトにガイドラインを取り込むために、誰かが抜粋を貼り付けます。コピーは元の内容が変更されたその日から古くなり、各翻訳がどのバージョンに基づいていたのか、誰にもわからなくなります。

**コンテンツは、翻訳が行われる場所よりも多くの場所で作成されます。** プロダクトの文字列はGitHub経由でリリースされます。マーケティングページはCMS経由で公開されます。サポート記事、メール、広告、営業資料も、それぞれ異なる経路で制作されます。TMS内でしか適用されない用語集では、TMSを通らないコンテンツをカバーできません。

**レビューでは、ポリシーではなく言語を確認します。** 言語レビュー担当者は、流暢さや正確さの確認に長けています。しかし、ドイツ語の広告では比較表現が禁止されているという請求ポリシー第3.2条について、常に知らされているとは限らないため、見落とすことがあります。

**現在公開されている内容を確認する仕組みはありません。** ガバナンスの大半は公開前に行われます。公開後はページが編集され、文字列が新たな文脈で再利用され、ルールが変更された後も古いコピーが長期間掲載されたままになります。

## ステップ 1: 各ルールの担当者を決める

ツール導入の前に、担当を明確にしましょう。各ルールには責任者を1人置き、その責任者は、すでにそのルールを管理している人にしてください。

| ルールの種類                          | 通常の担当者                  |
| ---------------------------------- | ---------------------------- |
| ブランドボイス、トーン、メッセージング | ブランドまたはコンテンツチーム |
| 製品および機能に関する用語    | 製品マーケティングまたは製品 |
| 言語ごとの用語集の訳語  | ローカライズチーム            |
| 主張、開示、法的文言 | 法務またはコンプライアンス          |
| 市場特有のすべきこと・してはいけないこと     | 地域マーケティングまたはGTM    |

これを実現する2つの原則：

- **担当者はコピーではなく、ソースを編集します。**法務部門が4つのツールで請求ポリシーを更新しなければならない場合、1つだけを更新し、残りは古いままになります。
- **ローカライズは調整役であり、すべてを担うわけではありません。** 公開前の最終工程であることから、ローカライズチームがブランドや法務に関するルールの事実上の管理者になってしまうことはよくあります。しかし、それでは規模を拡大できません。ローカライズチームの役割は、各言語でルールの所有者が定めたルールが確実に適用されるようにすることです。

## ステップ 2: ルールを適用できる程度に機械可読にする

60ページのブランドブックはオンボーディングには役立ちますが、ルールの徹底にはほとんど役立ちません。一貫して確認する必要のあるルールは、人間であれAIであれ、レビュー担当者が文が基準を満たしているかどうかを判断できるように書くべきです。

適切で執行可能なルールは次のとおりです:

- **具体的。**「ドイツ語の広告で『最高』や『業界をリードする』などの最上級表現を使わない」は確認できます。「自信を持ちつつ謙虚に」は確認できません。
- **適用範囲。** ルールが適用される市場、コンテンツタイプ、チャネルを指定します。
- **説明。** 理由を1行添えることで、レビュー担当者が例外的なケースに対処しやすくなり、AIモデルがルールを過剰に適用するのを防げます。
- **例示されています。** 合格例と不合格例を示すことで、曖昧さの大部分を取り除けます。
- **番号付き。** 安定した条項番号があることで、各フラグがどのルールに関するものかを正確に示せます。

用語については、少なくとも次の項目を含む用語集を維持してください：原語、ロケールごとに承認された訳語、禁止されている訳語、定義、品詞、および翻訳禁止かどうか。製品名、プラン名、法的に慎重な取り扱いが必要な用語には変更不可の印を付け、翻訳者やモデルによって決して「改善」されないようにしてください。

声のスタイルについては、全言語共通の説明を1つ作るのではなく、言語ごとにスタイルの注意事項を記述してください。フォーマル度（たとえば _du_ と _Sie_、_tu_ と _vous_ の使い分け、日本語の敬語レベル）、句読点や大文字・小文字の表記規則、読者への呼びかけ方は、言語ごとに一度決めて記録しておく必要があります。

## ステップ 3: 信頼できる唯一の情報源を維持し、コピーせずに参照する

ガバナンスにおいて最も効果的な変更は、ガイドラインを他のツールに貼り付けるのをやめることです。

代わりに、各ルールセットはその所有者がすでに使用しているシステムに残し、下流のすべてのステップをそのソースに接続します。法務部門がSharePointで開示文書を更新すると、誰かが再エクスポートしなくても、次の翻訳、レビュー、監査には新しい文言が使われます。

これにより、追跡可能性も確保できます。すべてのチェックが同じソースを参照していれば、「この翻訳は、どのバージョンのポリシーに照らしてチェックされたのか？」という、規制の厳しい業界では非常に重要な問いに答えられます。

使用している技術スタックに応じた実践的な方法:

- TMS の用語集とスタイルガイドは、手動でアップロードするのではなく、管理されたマスターにリンクしてください。
- ブリーフにPDFのスナップショットを添付する代わりに、ベンダーがガイドラインの原本にリアルタイムでアクセスできるようにします。
- AI翻訳やレビューを利用する際は、ガイドラインの抜粋をプロンプトにハードコードせず、リクエスト時に関連するガイドラインを取得してください。

For example, Hyperlocalise [Guidelines](/product/guidelines) connects to brand and policy files where they already live — Google Drive, Notion, and SharePoint — or lets teams type guidelines in directly. Agents read the connected file when they translate or review, and the file stays the source of truth: when legal updates the PDF, the next check uses the updated wording. Other teams achieve the same principle with TMS glossary sync, a headless terminology database, or a well-maintained internal wiki that every tool points to.

## ステップ 4: 最後だけでなく、コンテンツが書き込まれる場所でルールを適用する

最終レビューでしかチェックされないルールは、発見が遅れ、修正コストがかさみ、締め切りに追われてしばしば適用が免除されます。チェックはできるだけ早い段階で行いましょう。

**作成時。**ライターと翻訳者は、別のタブではなく、下書きの横に関連するルールが表示されるようにする必要があります。これには、原文に含まれる用語集の用語、対象ロケールの文体に関する注意事項、コンテンツタイプに適用される主張に関するルールが含まれます。

**AI翻訳では。**機械翻訳やLLMによる翻訳を使う場合、モデルにも人間の翻訳者と同じコンテキスト（用語集、文体の指針、適用されるポリシー）が必要です。そのコンテキストなしでモデルが流暢な文章を生成すると、一貫性の欠如があっという間に広がります。

**レビュー中。** ルールに基づいたチェックリストをレビュアーに提示し、指摘には必ず該当するルールを明記するよう求めます。「これは違和感があります」では議論が始まります。「これは第3.2条『ドイツ語の広告では最上級表現を使わない』に違反しています」なら、議論は終わります。

**公開前に。** 禁止用語、翻訳禁止用語の欠落、禁止フレーズ、必須の開示事項など、機械的に判定できる項目を自動チェックし、人間のレビュアーが判断を要する箇所に時間を割けるようにします。

Citation is what makes this auditable. When a flag points to a specific clause in a specific file, a reviewer can open the source instead of re-explaining the rule, and a compliance team can see exactly why a sentence was changed. Hyperlocalise agents work this way: they cite the clause in the connected guideline file when they flag a line, and in [Content Studio](/product/multilingual-content-studio) the attached file sits beside the draft so reviewers and agents are reading the same document.

## ステップ 5: 稼働中のものを継続的に監視する

ガバナンスは公開して終わりではありません。公開中のコンテンツは徐々にずれていきます：

- ページは翻訳ワークフロー外で、CMS上で直接編集されます。
- 古い文字列が、新しい文脈で再利用されており、現在は別の用語が適切です。
- ポリシーが変更されても、旧バージョンに準拠していたコピーは引き続き掲載されます。
- 新しい市場は、隣接するロケールからコンテンツをコピーして公開されます。

公開中のコンテンツも本番コードと同様に扱い、現行ルールに照らして定期的に確認し、見つかった問題を修正できる担当者に振り分けましょう。目指すのは、規制当局や顧客に指摘されてからではなく、ドイツ語版ホームページにコンプライアンス違反の訴求が掲載された翌朝に発見することです。

This can be a scheduled crawl with your own scripts, a periodic [localisation audit](/blog/what-is-a-website-localisation-audit), or an automated job. In Hyperlocalise, teams schedule an [Automation](/product/agents-automation) that checks product copy and live pages against the same connected guideline files every day, so flags show up in the morning instead of after a launch.

## ステップ 6: フィードバックを反映する

すべてのフラグは、内容だけでなく、あなたのガイドラインに関する情報でもあります。

- **同じルールに対するフラグの繰り返し**は通常、そのルールが不明確すぎる、範囲が広すぎる、または例が不足していることを意味します。
- **レビュアーによる上書き**は、市場に対してルールが誤っており、適用範囲を変更すべき箇所を示します。
- **原文に新しい用語が登場したら、20通りの異なる訳し方をする前に、用語集に登録するかどうかを判断してください。**
- **市場間の見解の相違**は、コメントスレッドで場当たり的に解決するのではなく、ルールの担当者に差し戻すべきです。

ルールのオーナーと定期的にこれらのシグナルを確認してください。ガバナンスシステムは、提示した判断がソースに反映されて初めて、時間とともに改善されます。

## コンプライアンスおよび規制対象コンテンツ：追加の管理措置

金融サービス、医療、製薬、ギャンブル、その他の規制対象カテゴリでは、上記に加えていくつかの管理策を追加します:

- **承認済みの固定文言。**開示事項および規制対象の文言は、毎回再翻訳するのではなく、承認済みのソースから挿入してください。
- **市場ごとの訴求表現に関するルール。** 主張できる内容は法域によって異なります。各ルールの適用範囲は、該当する市場に限定してください。
- 規制対象のコンテンツタイプでは、**人による承認が必須**であり、承認者とガイドラインのバージョンを記録します。
- **監査証跡**—公開された各文字列を、照合対象となったルールとその結果に結び付けるもの。
- **AI transparency obligations.** Where AI generates or translates customer-facing content, check whether disclosure rules apply. We covered one example in [what the EU AI Act Article 50 means for AI translation](/blog/what-the-eu-ai-act-article-50-means-for-ai-translation-and-localisation).

## ブランドと用語のガバナンスのためのツールを評価する方法

TMS、AIローカライゼーションプラットフォーム、あるいは社内開発のシステムを評価する場合でも、これらの質問によって、機能一覧と実効性のあるガバナンスを見分けられます。

1. **ルールはどこに保存されますか？** オーナーはガイドラインを既存のシステムに保管できますか？それとも、すべて再入力して手動で同期し続ける必要がありますか？
2. **ルールが変更されるとどうなりますか？** 後続のチェックには新しいバージョンが自動的に反映されますか？また、過去のチェックでどのバージョンが使われたか確認できますか？
3. **エンフォースメントはすべてのコンテンツ経路をカバーしていますか？** 製品内の文字列、CMSページ、ヘルプセンター、メール、広告など、TMSを経由するコンテンツだけではありません。
4. **AIモデルにはルールが与えられているのか？** 生成後の編集時だけでなく、生成時に用語集、文体、ポリシーのコンテキストを与える。
5. **フラグにはルールの引用がありますか？** 具体的な条項と出典が記載されているため、レビュー担当者やコンプライアンス担当者が確認できます。
6. **ライブコンテンツは監視されていますか？** 公開前のレビューだけでなく、現在のルールに基づく定期チェックを実施します。
7. **調査結果によってルールを改善できますか？** 繰り返し発生するフラグ、上書き、新しい用語を可視化します。

Most mature TMS platforms handle glossary and style-guide enforcement inside their own workflow well. The gaps usually appear at the edges: rules that live outside the TMS, content that never passes through it, and live pages that are never checked again. That is where an intelligence layer around existing tools tends to help — a pattern we described in [how to add AI translation without replacing your TMS](/blog/how-to-add-ai-translation-without-replacing-tms).

## 実践的な導入計画

すべてを一度に管理する必要はありません。段階的に導入する方が効果的です：

1. **棚卸し。** 現在、ブランド、用語、ポリシーのルールがどこにあり、それぞれを誰が管理しているかを一覧にします。
2. **まずは高リスクのルールから始めましょう。**製品名、翻訳禁止用語、規制対象の表現、必須の開示事項です。これらは最も確認しやすく、誤りがあった場合のコストも最も高くなります。
3. **コピーではなく、接続しましょう。** 翻訳、レビュー、AIの各ステップをソースファイルに接続します。
4. 決定論的ルールに**公開前チェックを追加**する。
5. トラフィックが最も多く、リスクが最も高いページの**ライブモニタリングを有効にする**。
6. 用語とコンプライアンスが安定したら、**音声と市場適応に拡張する**。
7. ルールの所有者と毎月フラグを確認し、ソースを更新します。

## よくある質問

### 用語ガバナンスとは何ですか？

用語ガバナンスとは、企業が使用する用語、各市場での翻訳方法、変更の承認者、そしてすべてのコンテンツにわたってそれらの決定を徹底する方法を定めるプロセスです。用語集、翻訳禁止リスト、使用禁止用語、新しい用語を追加するためのワークフローが含まれます。

### 用語集とスタイルガイドの違いは何ですか？

用語集では、機能、製品、概念を各言語でどう呼ぶかといった個々の用語を管理します。スタイルガイドでは、文章のトーン、丁寧さ、句読点、文体を管理します。多くのチームでは、ロケールごとに両方を整備する必要があります。

### 複数の言語でブランドボイスの一貫性を保つには、どうすればよいですか？

全体共通の説明を1つ作るのではなく、ロケールごとに文体ガイドを作成し、各言語での丁寧さや呼びかけ方を明確にしてください。すべての翻訳者、レビュアー、AIモデルに同じガイドを共有し、定期的に公開中のコンテンツがガイドに沿っているか確認してください。

### AI翻訳はブランドガイドラインに従えますか？

はい。翻訳やレビューの際にモデルにガイドラインが与えられ、出力が同じルールに照らして確認されていれば可能です。そのコンテキストがないAIは、流暢でもありきたりな文章を生成し、大規模に展開すると一貫性の欠如を助長しがちです。

### ガイドラインはTMS内に置くべきですか？

そうすることもできますが、必須ではありません。重要なのは、担当者が管理し、すべてのツールが参照する唯一の信頼できる情報源があることです。多くの企業では、ブランドブックはDrive、市場に関するメモはWiki、法的な文言はSharePointに保管しています。後続の工程が古いコピーではなく、それらの情報源を参照する限り、ガバナンスは機能します。

### 規制対象コンテンツへの準拠はどのように証明しますか？

公開された各コンテンツについて、どのルールのどのバージョンに照らして確認したのか、何が指摘されたのか、誰がいつ承認したのかを記録します。特定のソースファイル内の特定の条項を引用する指摘があれば、その記録をはるかに簡単に作成できます。

## 簡単に言うと

市場間の一貫性は、4つの要素から生まれます。明確な担当者、遵守を徹底できるルール、参照先となる唯一の信頼できる情報源、そして公開前後の両方で実行されるチェックです。ツールは役立ちますが、既存のルールの所在を尊重し、あらゆる判断をルールまで追跡可能にする場合に限ります。
